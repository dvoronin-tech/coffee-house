# 04: Обновить заявку тем же id

**What to build:** Повторная отправка с тем же id заменяет имя, телефон и заметку уже лежащей заявки. Время создания остаётся прежним, время изменения становится временем этой успешной отправки. Сайт получает код обновления, а не код создания. Знания id достаточно, входа нет.

**Blocked by:** 03: Отклонить заявку с плохими полями

**Status:** resolved

- [x] Повтор с существующим id обновляет имя, телефон и заметку и отвечает HTTP 200 с `{ code: "UPDATED" }`
- [x] Время создания при повторе не меняется. Время изменения обновляется при каждом успешном сохранении, даже если имя, телефон и заметка те же
- [x] Заметку можно очистить: пустая заметка и заметка из одних пробелов на повторе сохраняются как пустые
- [x] Новый телефон на повторе снова проверяется как белорусский и пишется как E.164
- [x] Если два создания с одним id приходят одновременно и второе застаёт уже созданную строку, второе обновляет её и возвращает `UPDATED`
- [x] Новый id по-прежнему создаёт другую заявку и возвращает `CREATED`, даже с тем же телефоном
- [x] Отказ по id, имени, телефону или заметке на повторе не меняет уже лежащую заявку
- [x] Тип маршрута, который импортирует сайт, различает код создания и код обновления
- [x] Аналитика по-прежнему не записывается
- [x] Автоматических тестов нет

## Comments

Реализовано на ветке `feat/hono`. Повтор того же id отвечает `UPDATED`.
