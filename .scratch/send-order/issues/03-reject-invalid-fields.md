# 03: Отклонить заявку с плохими полями

**What to build:** Сайт получает отдельный код отказа для плохого id, плохого имени, плохого телефона и слишком длинной заметки. Такая отправка не создаёт заявку и не меняет уже лежащую. Лишние поля верхнего уровня сохранению годной заявки не мешают.

**Blocked by:** 02: Сохранить новую заявку

**Status:** resolved

- [x] Пустой id, отсутствующий id, не-строка и строка длиннее 128 символов дают HTTP 400 и `{ code: "INVALID_ID" }`
- [x] Пустое имя после обрезки пробелов и имя длиннее 200 символов после обрезки дают HTTP 400 и `{ code: "INVALID_NAME" }`
- [x] Номер не из Беларуси или недействительный номер даёт HTTP 400 и `{ code: "INVALID_PHONE_NUMBER" }`
- [x] Заметка длиннее 2000 символов после обрезки пробелов даёт HTTP 400 и `{ code: "INVALID_NOTE" }`
- [x] Любой из этих отказов не создаёт строку и не меняет имя, телефон, заметку и время уже лежащей заявки
- [x] Неизвестные поля верхнего уровня отбрасываются и не дают отказа
- [x] Кодов `INVALID_ANALYTICS` и `INVALID_BODY` нет
- [x] Годная новая заявка по-прежнему сохраняется с кодом `CREATED`. Тип маршрута, который импортирует сайт, включает эти коды отказа
- [x] Автоматических тестов нет

## Comments

Реализовано на ветке `feat/hono`. Плохие поля отвечают своим кодом и не меняют заявку.
